# XS-2026-0008 公网 UDP 与回环 HTTP 无法独立绑定

- 标题：Compose 共用绑定地址导致公网节点与管理面 TLS 边界冲突
- 严重级别：P1
- 发现时间：2026-08-02 UTC
- 环境：域名测试部署、Docker Compose、外部 `1panel-network`
- 版本和提交：远端 `26440cc`
- 前置条件：Controller/Console 必须只在回环监听，外部 Agent 同时需要访问 Discovery 和 Relay UDP
- 复现步骤：设置 `XS_BIND_ADDRESS=127.0.0.1` 时检查 UDP 发布；再设置为 `0.0.0.0` 检查 Controller/Console HTTP 发布
- 期望：HTTP 固定回环并由 TLS 反向代理公开；UDP 可在显式批准后独立公开
- 实际：三类端口共用一个变量，无法同时满足两项要求
- 日志：`/srv/xs-nexus/artifacts/qa/domain-integration-20260802T111905Z`
- 截图：不适用
- 根因：早期隔离部署只验证本机生命周期，没有建模真实外部 Agent 的 UDP 入站需求
- 修复：新增 `XS_UDP_BIND_ADDRESS`；Discovery/Relay 使用该变量，HTTP 保持 `XS_BIND_ADDRESS`；预检强制 HTTP 回环并限制 UDP 为回环或全 IPv4 监听
- 回归测试：Compose 预检、M5.2 生命周期、实际 socket、HTTPS/WSS 和外部 Agent 路径
- 相关提交：`fix(deploy): separate public UDP from private HTTP bindings`
- 状态：已关闭
