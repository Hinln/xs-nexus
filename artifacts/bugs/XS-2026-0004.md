# XS-2026-0004 稳定性门禁误解 Docker 手动重启计数

- 标题：长测强化错误要求手动 `docker restart` 增加 `.RestartCount`
- 严重级别：P2
- 发现时间：2026-08-01 14:37 UTC
- 环境：Ubuntu 26.04 LTS，Docker Compose，运行中的 24 小时稳定性测试
- 版本和提交：`bc5bf20`
- 前置条件：Controller、Relay 和 Console 正常运行，由测试在中点依次执行 `docker restart`
- 复现步骤：检查 `/srv/xs-nexus/artifacts/qa/runtime-stability-20260731T212242Z/resources.csv`；三个服务均出现一次 PID 变化，但每个样本的 `restart_count` 都为零
- 期望：门禁区分测试主动注入的一次手动重启与 restart policy 触发的额外自动重启
- 实际：初版断言要求 `max(restart_counts) >= baseline + 1`，会拒绝正常的手动重启；重启命令还使用已弃用的 `--time`，其警告混入证据文件
- 日志：同一证据目录中的 `restart-controller.txt`、`restart-relay.txt` 和 `restart-console.txt` 均先记录弃用警告，再记录正确的完整容器 ID
- 截图：不适用
- 根因：把 Docker daemon 的 restart-policy 计数错误地当作所有启动周期的通用计数，没有先用真实手动重启证据核对字段语义
- 修复：使用 `docker restart --timeout 20`；要求输出仅有一行且精确等于目标完整容器 ID；每个服务必须恰好观察到两个 PID；所有 `RestartCount` 样本必须等于基线，任何自动重启均失败关闭
- 回归测试：`bash -n scripts/test-runtime-stability.sh` 和合成证据正负检查先行；活动 24 小时测试结束并释放 Compose 环境后执行短时真实集成回归
- 相关提交：远端 `82f0d40`（`fix(stability): correct manual restart evidence`）
- 状态：已关闭
