# XS-2026-0009 官方 Caddy 文件能力与零 capability 运行边界冲突

- 标题：官方 Caddy 二进制在严格降权容器中无法执行
- 严重级别：P1
- 发现时间：2026-08-02 UTC
- 环境：Caddy 2.10.2 Alpine、Docker、`cap_drop: ALL`、`no-new-privileges`
- 版本和提交：公网 Edge 初版
- 前置条件：Edge 以 UID 65532、只读根文件系统、零 capability 启动
- 复现步骤：运行 Edge 预检的隔离 `caddy validate`
- 期望：Caddy 在容器内部高端口 8080/8443 上无需 capability 即可运行
- 实际：官方二进制携带 `cap_net_bind_service=ep`，tini 在已清空 capability bounding set 的容器中返回 `Operation not permitted`
- 日志：`/srv/xs-nexus/artifacts/qa/domain-integration-20260802T111905Z/setup.log`
- 截图：不适用
- 根因：官方镜像面向容器内直接监听 80/443，而项目通过 Docker 端口映射使用高端口，继承该文件能力既不需要也不兼容更严格的运行策略
- 修复：从固定官方 digest 构建 Edge 镜像，升级基础包后用 `setcap -r` 移除文件能力；最终镜像固定 UID 65532、OCI revision、空 entrypoint 和明确 Caddy 命令
- 回归测试：零 capability、no-new-privileges、只读根和非 root 下真实 `caddy validate` 通过；随后执行 HTTPS/ACME 和公开入口集成
- 相关提交：`fix(edge): remove unnecessary low-port file capability`
- 状态：已关闭
