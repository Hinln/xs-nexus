# XS-2026-0005 更新通道无法由控制面安全激活

- 标题：灰度策略可创建，但节点通道只来自 Agent 静态配置
- 严重级别：P1
- 发现时间：2026-08-01 UTC
- 环境：Controller、Agent、Console 与真实 PostgreSQL 隔离测试栈
- 版本和提交：签名更新通道初版
- 前置条件：已导入离线签名发布，并为 testing 或 development 通道创建灰度策略
- 复现步骤：在 Console 创建非 stable 策略；节点继续按 Agent 本地静态通道上报，且既有长连接缓存认证时的通道值
- 期望：管理员通过已签名的网络配置分配节点通道；Agent 只接受自身签名节点条目，Controller 每次按数据库当前分配核验报告
- 实际：策略无法由控制面激活；若数据库被手工修改，既有连接还会按旧快照错误拒绝新报告
- 日志：真实 PostgreSQL 更新集成和 Agent 控制回归
- 截图：Console 更新管理 Playwright 回归
- 根因：节点通道被错误建模成仅 Agent 本地配置，连接认证对象还持有可陈旧的授权快照
- 修复：把节点通道纳入 Controller 签名配置；管理 API 通过网络配置版本发布并审计；Agent 从自身签名节点条目取值并立即重报；Controller 每次读取数据库当前分配
- 回归测试：成功切换、旧配置版本 409、签名 payload、审计脱敏、Agent 重报、十条 Console 主流程和六视口视觉回归均通过

- 状态：已关闭
