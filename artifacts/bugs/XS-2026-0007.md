# XS-2026-0007 Windows CLI 不可编译且本地 IPC 会死锁

- 标题：`xs-cli` 依赖 Unix socket，EOF 分帧无法安全移植到 Windows duplex Named Pipe
- 严重级别：P1
- 发现时间：2026-08-02 UTC
- 环境：Linux Agent/CLI 与 `x86_64-pc-windows-msvc` 交叉编译门禁
- 版本和提交：远端 `e272114`
- 前置条件：使用 Windows target 构建 CLI，或尝试以 Named Pipe client 复用原 EOF 请求边界
- 复现步骤：对 `xs-cli` 执行 MSVC target check；随后分析服务器 `read_to_end` 和 Windows duplex Named Pipe 客户端的请求/响应等待关系
- 期望：Windows CLI 可编译；Unix stream 与 Windows Named Pipe 使用相同、有界且不依赖半关闭的消息边界
- 实际：CLI 无条件导入 Tokio UnixStream，Windows target 编译失败；简单替换成 Named Pipe 后，服务器等待 EOF、客户端等待响应，双方会死锁
- 日志：`/srv/xs-nexus/artifacts/qa/final-local-audit-20260802T102009Z`
- 截图：不适用
- 根因：初版只验证 Windows 服务器 crate，未把 CLI 纳入交叉门禁；流协议错误依赖 Unix 写半边 EOF
- 修复：请求和响应统一使用 4 字节无符号大端长度加严格 JSON，一连接一请求；请求上限 4 KiB、响应上限 512 KiB；Windows CLI 使用固定 Named Pipe client，无 unsafe；server/client 拒绝零、超限、截断和错误响应类型
- 回归测试：Linux Agent IPC 和 CLI 协议/退出码测试、严格 Clippy、Windows server/client MSVC check 与交叉 Clippy通过；真实 Named Pipe、DACL、SCM 和九命令 Windows 运行仍由 `BLK-001` 阻塞
- 相关提交：`feat(cli): make local IPC portable across Unix and Windows`
- 状态：已关闭
