# Windows installation (Wintun adapter exception)

Status: Windows 11 x64 test release path. It is not a Release Candidate or a claim of independently audited production security.

## Install

Open a 64-bit Windows PowerShell session **as Administrator**, then run:

```powershell
irm https://vpn.qinwen.co/install | iex
```

Enter a single-use enrollment token generated by the XS Nexus Console when prompted. The token is read as a secure value and written only to a temporary ACL-protected file for the enrollment request; it is not passed as a command-line argument.

The Linux command is different:

```bash
wget -qO- https://vpn.qinwen.co/install | sudo bash
```

`GET /install` selects the Windows script only for a PowerShell User-Agent. Do not use `wget` for Windows installation.

## What the bootstrap verifies

Before creating `C:\ProgramData\XS Nexus`, the bootstrap downloads only over HTTPS and verifies:

- a release-manifest SHA-256 embedded in the bootstrap;
- exact product, version, platform, target, archive filename, size and archive SHA-256;
- the exact payload allowlist and SHA-256 of every payload member;
- official Wintun `0.14.1` x64 DLL SHA-256 and a valid Authenticode signer subject of `CN=WireGuard LLC`.

It installs `xs-agent.exe`, `xs.exe`, `wintun.dll`, the Wintun prebuilt-binary license, protected Agent state, and a LocalSystem `XsNexusAgent` service. Existing Windows installations are rejected rather than overwritten.

## Check the local node

After successful enrollment and service startup:

```powershell
& 'C:\ProgramData\XS Nexus\bin\xs.exe' status
& 'C:\ProgramData\XS Nexus\bin\xs.exe' peers
& 'C:\ProgramData\XS Nexus\bin\xs.exe' netcheck
```

## Scope and limitations

The Windows adapter is an explicit user-approved exception to the original no-third-party-adapter policy. Wintun provides only the signed Layer-3 adapter and packet session. XS Nexus retains its own identity, control plane, XSP/1 transport, encryption, ACL, routing policy, NAT traversal and relay implementation.

This path is currently limited to Windows 11 x64 test validation. Windows subnet-route advertisement is fail-closed, and automatic Windows update/upgrade/rollback and the full Windows service/network lifecycle need separate evidence. See `DECISIONS.md` ADR-077 and `THIRD_PARTY.md` for the release pin and license boundary.
